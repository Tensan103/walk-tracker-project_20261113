# タスク: 画面2「実績」の新規作成と3画面ナビゲーション構成への更新 (Step 2-6)

## 1. 目的と背景
Phase 2 の管理画面拡張の仕上げとして、デバイスごとの歩きスマホ検知件数（`DETECT` 件数）を集計・一覧表示する画面2 **「実績」** を新規作成する。
あわせて、管理画面のナビゲーションを **「タイムライン」「実績」「デバイス管理」** の3画面構成へ更新する。
※本タスクではバックエンドAPIおよび画面3「デバイス管理」は変更しない。

## 2. 対象コンポーネント
- `/admin-web-viewer` 配下のファイル
  - `src/App.tsx` (3画面構成へのナビゲーション更新)
  - `src/components/StatsScreen.tsx` または `src/pages/StatsScreen.tsx` (新規作成: 既存プロジェクトのディレクトリ構成に合わせること)
  - Step 2-4 で作成した `src/utils/eventProcessing.ts` (`aggregateDeviceStats`, `getCurrentMonthRangeJst`), `src/components/Pagination.tsx` の利用

## 3. 実装要件

### 3-1. ナビゲーションの3画面構成化 (`src/App.tsx`)
- ヘッダー（またはサイドバー）のナビゲーションタブを以下の3画面構成にする。
  1. **タイムライン** (既存・デフォルト表示)
  2. **実績** (新規追加)
  3. **デバイス管理** (既存・変更なし)

### 3-2. データ取得と集計 (`StatsScreen`)
- 画面マウント時および「最新データに更新」ボタン押下時に、`GET /events` と `GET /devices` を `Promise.all` で並列取得する。
- 取得したデータと現在の日付範囲条件を `aggregateDeviceStats(events, devices, startDate, endDate)` に渡し、`DeviceStat[]` を生成する。
  - 登録済みデバイスは検知件数が `0` でも一覧に表示されること。
  - `DevicesTable` に未登録の `deviceId` で検知があった場合も一覧に表示されること（`userName` が `"未登録"` の場合はグレー文字等で視覚的に区別）。
- ローディング表示・エラー表示はタイムライン画面と統一感のあるUIにすること。

### 3-3. 日付範囲フィルタ（デフォルト: 当月初日〜末日）
- テーブル上部に `<input type="date">` を2つ配置し、「開始日 〜 終了日」で集計対象期間を絞り込めるようにする。
- **初期値**: `getCurrentMonthRangeJst()` を用いて、現在の月（JST基準）の初日〜末日をデフォルト設定する。
- 期間を変更した後にすぐ戻せるよう、「今月にリセット」ボタン（および必要に応じて全期間表示用のクリアボタン）を配置する。

### 3-4. テーブル列構成とソート機能
- 一覧表の列構成は以下の通りとする。
  1. **デバイス名**: `deviceModel`（未登録時は `"-"`）
  2. **ユーザー名**: `userName`（未登録時は `"未登録"`）
  3. **デバイスID**: `deviceId`
  4. **検知件数**: `detectCount`（例: `12件` または数値表示）
- **ソート機能**:
  - **「検知件数」** 列のヘッダークリック（またはソートUI）で昇順・降順を切り替えられるようにし、現在の向き（`▲` / `▼`）を表示する。
  - **デフォルト**: 検知件数の **降順**（件数が多い順）。同数の場合は `deviceId` 昇順等で順序を安定させること。

### 3-5. ページネーション（20件ごと）
- 集計・ソート済みの配列に対して、`Pagination` コンポーネント（`pageSize = 20`）を適用し、1ページあたり最大20件を表示する。
- **ページリセット**: 日付範囲フィルタやソート順が変更された場合、`currentPage` を自動的に `1` にリセットすること。

## 4. 実行手順
1. ブランチ `feature/admin-stats-view` を作成して切り替える。
2. `StatsScreen` を新規作成し、`src/App.tsx` に3画面目のタブとして組み込む。
3. `cd admin-web-viewer` にて `npm test` および `npm run build` を実行し、全テストのパスとTypeScriptビルドエラーがないことを確認する。
4. 変更をコミットし、実装内容とローカルでの動作確認ポイント（当月デフォルト集計・0件デバイス表示・件数ソート・3画面切り替え）を報告する。
