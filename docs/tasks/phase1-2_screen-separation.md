# タスク: メイン画面とデータロガー画面の分離 (UI Refactoring)

## 1. 目的と背景
現在の `SensorLoggerScreen` にすべての機能が混在している状態を解消する。
本番向けの「歩行検知メイン画面」と、検証（レガシー）向けの「データロガー画面」に分離し、下部タブ（Bottom Navigation）で切り替えられるようにする。

## 2. 対象コンポーネント
- `/android-app` 配下のUI関連ファイル（`MainActivity.kt` および新規作成するComposeファイル）
- `app/build.gradle.kts` (Navigationライブラリの追加)

## 3. 実装要件

### 3-1. 依存関係の追加
- Jetpack Navigation Compose (`androidx.navigation:navigation-compose`) を導入すること。

### 3-2. 画面構成 (Bottom Navigationの導入)
以下の2つの画面（Composable）を作成し、下部タブで切り替えられるルーティングを実装すること。

#### ① MainScreen (歩行検知アプリ画面)
- **役割**: 本番用UI。画面ON時に現在のステータスをシンプルに表示する。
- **UI要件**:
  - 中央に大きくステータスを表示するのみ。
  - ステータスは2種類：「監視中」（グレーや青基調）と「歩行検知！」（赤基調）。
  - （※状態は `SensorRepository` 等の StateFlow から監視して自動更新すること）

#### ② LoggerScreen (データロガー画面 / レガシー扱い)
- **役割**: 従来のデータ検証用ツール。普段は停止している。
- **UI要件**:
  - これまで作成した「加速度のX,Y,Z表示」「累計歩数」「検証メモのテキストボックス」「記録開始/停止ボタン」をすべてこの画面に移動する。
  - 記録開始ボタンを押した時のみ、CSVへのロギング処理が走るようにする。

### 3-3. 状態管理の分離・整理
- LoggerScreenの「記録(ロギング)」状態と、MainScreenの「歩行判定」状態が干渉しないように整理すること。
- メイン画面が表示されていても、ロガーがOFFであればCSV書き込みは行われないこと。

## 4. 作業手順
1. ブランチ `feature/separate-screens` を作成する。
2. 上記の要件に従い、UIの分割とNavigationの実装を行う。
3. コードの変更をコミットし、完了を報告する。
