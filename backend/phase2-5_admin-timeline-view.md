# タスク: 画面1「タイムライン」の改修（ペアリング表示・フィルタ・ソート・ページネーション） (Step 2-5)

## 1. 目的と背景
Step 2-4 で実装したデータ処理ロジック（`eventProcessing.ts`）と共通ページネーション部品（`Pagination.tsx`）を既存の歩行検知履歴画面に組み込み、画面1「タイムライン」として改修する。
※本タスクではバックエンドAPIおよび「デバイス管理」画面は変更しない。また、画面2「実績」は次ステップ（Step 2-6）で実装する。

## 2. 対象コンポーネント
- `/admin-web-viewer` 配下のファイル
  - `src/App.tsx` (タブ名・見出しの「タイムライン」への改名)
  - 既存の履歴一覧コンポーネント（または新規 `src/components/TimelineScreen.tsx` / `src/pages/TimelineScreen.tsx` への切り出し）
  - Step 2-4 で作成した `src/utils/eventProcessing.ts`, `src/components/Pagination.tsx` の利用

## 3. 実装要件

### 3-1. 画面名・ナビゲーションの更新
- 既存の「歩行検知ダッシュボード」（履歴画面）のナビゲーションタブ名および画面見出しを **「タイムライン」** に変更する。

### 3-2. ペアリング表示とテーブル列構成
- `GET /events` で取得した生イベント配列を `pairWalkEvents()` に通し、`PairedWalkEvent[]` としてテーブルに表示する。
- テーブルの列構成は以下の通りとする。
  1. **検知日時 (JST)**: `detectTimestamp` を日本時間フォーマットで表示
  2. **解除日時 (JST)**: `releaseTimestamp` を日本時間フォーマットで表示（`null` の場合は `"-"`）
  3. **時間**: `formatDuration(durationMs)` の結果を表示（`null` の場合は `"-"`）
  4. **デバイス名**: `deviceModel`（未登録時は `"-"`）
  5. **ユーザー名**: `userName`（`"未登録"` の場合はグレー文字等で視覚的に区別）
  6. **デバイスID**: `deviceId`
- 既存の「最新データに更新」ボタン、ローディング表示、エラー表示は維持する。

### 3-3. 検索フィルタ機能
テーブル上部にフィルタバーを配置し、すべてフロントエンド側（`useMemo` 等）で絞り込みを行う。デフォルトはすべて未入力（フィルタなし）。
- **検知日時**: `<input type="date">` を2つ配置し、「開始日 〜 終了日」の範囲指定で絞り込む（`isWithinJstDateRange(detectTimestamp, startDate, endDate)` を使用）。
- **デバイス名**: テキスト入力による部分一致検索（大文字・小文字を区別しない）。
- **ユーザー名**: テキスト入力による部分一致検索（大文字・小文字を区別しない）。
- **クリアボタン**: 入力中のフィルタ条件を一括で初期状態に戻すボタンを配置する。

### 3-4. ソート機能
以下の3列について、テーブルヘッダークリック（またはソートUI）で昇順・降順を切り替えられるようにする。現在のソート対象列と向き（`▲` / `▼` 等）が視覚的に分かるように表示すること。
- **対象列**: 検知日時（`detectTimestamp`）、時間（`durationMs`）、デバイス名（`deviceModel`）、ユーザー名（`userName`）
- **デフォルト**: 検知日時の降順（新しい順）
- **`"-"` / `null` の扱い**: `compareNullable` 等のヘルパーを用い、値が `null` または `"-"` の行は昇順・降順にかかわらず**常に末尾**に配置すること。

### 3-5. ページネーション（20件ごと）
- フィルタ・ソート適用後の配列に対して、`Pagination` コンポーネント（`pageSize = 20`）を適用し、現在のページに該当する最大20件のみを表示する。
- **ページリセット**: 検索フィルタ条件やソート条件が変更された場合、`currentPage` を自動的に `1` にリセットすること。

## 4. 実行手順
1. ブランチ `feature/admin-timeline-view` を作成して切り替える。
2. 上記要件に従い、タイムライン画面の改修（必要に応じてコンポーネント分割）を行う。
3. `cd admin-web-viewer` にて `npm test` および `npm run build` を実行し、既存テストのパスとTypeScriptビルドエラーがないことを確認する。
4. 変更をコミットし、実装内容とローカルでの確認ポイント（フィルタ・ソート・ページネーションの挙動）を報告する。
